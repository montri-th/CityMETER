# CityMETER live visual evidence and capture QA

**Inspection date:** 13 August 2026 (Asia/Bangkok)  
**Scope:** Read-only visual inspection of the current public CityMETER implementation and public Landometer assets.  
**Purpose:** Source note for landing-page imagery, hero motion, captions, and release QA. This note does not certify dataset accuracy, rights, coverage, methodology, or production brand approval.

## Reading this note

- A value under **Visible state** records what the public interface displayed during inspection. It is not an approved evergreen marketing claim.
- **Settle time** is a conservative capture wait observed or needed on this inspection connection, not a performance SLA. Hard-load the exact URL for every take and capture only after tiles, polygons, legends, rankings, and charts stop changing.
- A working route proves that a public view was reachable. It does not by itself prove completeness, smallest geography, geometry type, freshness, licensing, or suitability for a decision.
- Do not use the browser title as the sole capture label. One inspected tab showed a Shopping Center URL while `document.title` still said Population. Verify the URL, visible dataset heading, selected state, and title together before every take.

### Design System 0.8.9 release note

Design System 0.8.9 requires a normal header to use the exact approved transparent **horizontal Landometer lockup** with an asset ID, exact variant, SHA-256, approved surface pairing, clear-space rule, minimum delivered size, theme/backdrop scope, and current Brand identity approval. It permits the symbol alone only in an approved compact, app-icon, or favicon context and prohibits redrawing, tracing, recolouring, cropping, masking, or reconstructing the logo.

The owner supplied a transparent horizontal artwork for this revision, and the prototype preserves its exact source bytes plus a proportional web derivative. Before production cutover, record the governed asset ID, approved surface pairings, clear space and minimum CSS size in the Brand identity registry; this is a documentation gate rather than a missing-asset blocker for the current GitHub review build.

## Cross-cutting URL and release QA

- At inspection time, `https://www.landometer.com/citymeter` still served a legacy Next.js `/citymeter` shell and client-side navigation could land on `https://landometer.com/v3/citymeter?d=population`. The new catalog launch must replace or disable this legacy behaviour without breaking the `/v3/citymeter?...` dataset views.
- Current dataset views did not expose a canonical link during inspection. The catalog should have one self-canonical host URL, with the other host variant permanently redirected rather than both returning `200`.
- Deep dataset links should remain exact `/v3/citymeter[/{scope}]?d={key}` action URLs. The landing-page dataset description and its live-app action are different objects; do not imply that a mutable SPA state is a complete crawlable dataset record.
- Re-run URL, heading, title, selected-state, map-settle, attribution, source/date, and limitation checks on the final deployment date. Dynamic figures and forecast timestamps in this note should not be copied into evergreen landing-page prose without a current evidence record.
